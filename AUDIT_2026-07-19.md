## 0. Verdict en une page

**Le cœur du produit est réel et fonctionne.** 216 uploads réels vers Gemini
sont dans le corpus (tous avec URL tracker persistée), la suite compte **1610
tests** (collectés et exécutés verts), la philosophie déterministe / human-in-the-loop
est authentiquement implémentée (aucun tag générique `FRENCH` uploadé, les 80
packages `MULTi` sans variante sont tous bloqués à un score < 60). Un amateur qui
suit l'outil sur un **film standard bien nommé** produit effectivement un package
propre. C'est un vrai produit, pas une maquette.

**Mais la couche qui garantit la conformité a des trous que le corpus prouve, pas
que je suppose.** Trois constats résument la gravité :

1. **Un encode de la team interdite EXTREME est déjà uploadé sur le tracker**
   (`Jeune.Juliette.2019...x264-EXTREME`, id 26362, score 100 « parfait ») parce
   que le check C9 est **inversé par rapport au PDF** — il bloque le contenu
   autorisé et laisse passer l'interdit.
2. **29 packages à team bannie (Slay3R) sont en état `prepared` donc uploadables**,
   parce que le blocage compliance `FAILED` est **annulé une seconde plus tard**
   par le dedup-check qui repasse le package en `prepared`.
3. **Blade Runner 2049 est identifié comme Blade Runner (1982)** et affiché
   à 98/100 « quasi parfait » — deux agents l'ont trouvé indépendamment. La regex
   année accepte `2049`, jette le vrai `2017`, et le score vidéo n'a **aucun
   garde-fou de cohérence nom↔TMDB** (celui-ci existe pourtant déjà côté livres).

Ces trois-là ne sont pas des hypothèses : les states, les IDs d'upload et les
`debug.json` sont dans le corpus. Le système de confiance, censé être le filet
de sécurité, **ment dans ~1 cas sur 6** au-dessus de 95 (47 packages non conformes
affichés ≥ 90, dont 16 déjà uploadés).

**En face, la gouvernance documentaire s'est effondrée.** `CLAUDE.md` — lecture
obligatoire injectée à chaque session — décrit depuis 2 mois un projet en
`v0.3.17` avec « 772 tests » et « v0.5.0 en planification », alors que v0.5.0 est
publiée, que les tests sont 1610, et que 46 sprints ont été livrés depuis. Une
**clé API imgbb traîne en clair dans `NOTES.md` commité sur le repo public**.

**Notes globales** : Fond 6/10 · Forme (UX) 6/10 · Conformité charte 5/10 ·
Structure/DX 4/10. **Le produit est à ~1 release complète de retard sur son
propre code, et son filet de conformité a des mailles trouées que seul un audit
corpus révèle.** La bonne nouvelle : la quasi-totalité des BLOQUANTS sont des
fixes **S/M** ciblés, pas des refontes.

**163 findings** : 13 BLOQUANT, 51 MAJEUR, 65 MODÉRÉ, 34 MINEUR.

## 1. Cahier des charges implicite (ce que promet Flox, à qui, comment)

**Quoi** : un outil desktop Windows (web UI locale FastAPI + installeur `.exe`)
qui, à partir d'un fichier ou dossier, génère un release name scene-compliant
selon la charte Gemini (fork Unit3D « G3MINI »), le `.torrent`, le NFO MediaInfo,
la fiche BBCode, détecte les doublons via l'API tracker, calcule un score de
confiance, et uploade — le tout **sans terminal** et **sans jamais livrer un
package non conforme**.

**Pour qui** : un uploadeur amateur francophone, mono-utilisateur, sur son PC
(pas de serveur, pas de NAS, pas de multi-tenant).

**Comment** : 100 % déterministe (aucun LLM), human-in-the-loop (signale les
ambiguïtés au lieu de deviner), atomic writes, dégradation gracieuse (jamais de
mur sur un type de contenu).

**Promesse vs livré** : le cœur vidéo (films, un peu séries) est livré et éprouvé.
La v0.5.0 a ajouté **les livres** (1 catégorie sur les 10 promises par D-MC1) ;
jeux / TV / sport / logiciels / formations glissent en v0.6.0+. Le problème n'est
pas le glissement (raisonnable) mais qu'il n'est **acté nulle part dans le plan
canonique** (PLAN-MULTICAT jamais amendé) et que **l'UI elle-même (`/guide`)
affirme le contraire** en listant « Ebooks : pas encore géré ».

### BLOQUANT (13)

**F001 · [B1 Langue] Tag VFx explicite écrasé par la variante TMDB du mauvais pays (dict vf_to_vo mort) — tag faux à score 100**
- *Où* : src/flox_uploader/core/release_name.py:427-432 (CAS 2 de merge_multi_language) ; corpus : data/upload_packages/Les.Invasions.Barbares.2003.VOF.1080p.BluRay.DTS5.1.x265-AZAZE
- *Preuve* : Code : `vf_to_vo = {"VFF": "VOF", "VFQ": "VOQ", "VFB": "VOB"}` puis `if t.upper() in vf_to_vo: upgraded.append(tmdb_variant)` — la valeur du dict n'est JAMAIS lue. Matrice exécutée : VFQ + TMDB fr(France) → VOF ; VFF + TMDB fr(Canada) → VOQ. Corpus : Les.Invasions.Barbares.2003 (stem team = « ...VFQ.1080p... », film québécois de Denys Arcand, TMDB ol=fr countries=['Canada','France']) réécrit VOF, state=prepared, score=100 bucket=parfait, naming_signals=[].
- *Pourquoi* : PDF RÈGLES_DE_NOMMAGE p.4 : « VOF : Version Originale Française » vs « VOQ : Version Originale Québécoise ». Un film québécois taggé VOF ment sur l'origine de la piste, et le score 100 signifie « upload les yeux fermés » (CLAUDE.md §7). La règle « France domine » d'infer_fr_variant_from_tmdb (release_name.py:316-319) écrase l'info explicite de la team sur les coproductions.
- *Solution* : Remplacer `upgraded.append(tmdb_variant)` par `upgraded.append(vf_to_vo[t.upper()])` ; si vf_to_vo[t] ≠ tmdb_variant (région du tag ≠ région TMDB dominante), émettre un signal review au lieu de convertir silencieusement. Ajouter le test Invasions Barbares (VFQ + coprod Canada+France → VOQ) dans test_merge_multi_language.py. — effort **S**

**F002 · [B2 Audio/Vidéo] `_has_encode_library` est une tautologie : la règle « WEB untouched → H.264/H.265 » ne s'applique jamais**
- *Où* : src/flox_uploader/core/release_name.py:521-534 (_has_encode_library) + src/flox_uploader/core/mediainfo_parser.py:88-100 (_normalize_video_codec) + release_name.py:571-576
- *Preuve* : Sortie générée : _normalize_video_codec('AVC')='AVC / x264' → _has_encode_library=True ; idem pour HEVC/H.264/H.265 (4/4 True). Le parser renvoie TOUJOURS la chaîne 'AVC / x264'/'HEVC / x265' pour tout média AVC/HEVC, avec ou sans writing library. Corpus : sur 111 packages avec source WEB/WEB-DL (38 WEB-DL + 73 WEB), vcodec final = x264/x265 dans 100 % des cas, zéro H.264/H.265. PDF RÈGLES_DE_NOMMAGE p.5 : « Pour les flux untouched (WEB, HDTV) : H.264, H.265, VP9, AV1 » ; PDF FULL_REMUX p.4 : « Un WEB-DL est un flux de plateforme dit "untouched" ».
- *Pourquoi* : Le cas 2 de infer_video_codec (WEB → H.26x sauf encode confirmé) est du code mort dès que MediaInfo est présent : has_encode_library vaut systématiquement True. Tous les WEB-DL untouched sont donc étiquetés comme des encodes (x26x), en violation directe du PDF. CLAUDE.md §5 étape 11 (« MediaInfo arbitre ») décrit un comportement qui n'existe pas.
- *Solution* : Exposer le vrai champ writing library dans le parser (MediaInfo JSON : `Encoded_Library` / `Encoded_Library_Name` / présence de `Encoded_Library_Settings`) dans un champ dédié `video.writing_library`, et faire lire ce champ (pas `video.codec`) par _has_encode_library. Ajouter un test : WEB-DL + AVC sans writing library → H.264 ; avec x264 core → x264. — effort **M**

**F003 · [B3 Mapping API] season_number/episode_number omis du POST pour les catégories 6, 14 et 15 (envoyés seulement si category_id == 2)**
- *Où* : src/flox_uploader/core/gemini_api.py:355 (to_form_data), POSTé via upload_torrent gemini_api.py:814
- *Preuve* : Code : `if self.category_id == 2:  # TV` seul cas où d['season_number'] est ajouté. Sortie générée (script audit_b3_mapping.py §6) : cat 2 → envoyés True ; cat 6 (Séries Animations) → False ; cat 14 (Séries Documentaires) → False ; cat 15 (Émission TV) → False. PDF TORRENT_API.txt p.2 : « Séries : si votre catégorie a « Série (TMDB) : oui », vous devez envoyer season_number et episode_number » ; tableau p.4 : Série(TMDB)=oui pour 2, 14, 6, 15. L'UI elle-même connaît la bonne liste : package_detail.html:2349 `tvCats = [2, 6, 14, 15]` affiche le champ saison pour ces 4 cats — mais la valeur saisie ne partira jamais.
- *Pourquoi* : Toute série d'animation (cat 6, AUTO-détectée via genre TMDB Animation) ou série documentaire (cat 14, auto) ou émission TV (cat 15, override recommandé par l'UI) sera rejetée par la validation du tracker, ou pire uploadée sans méta saison/épisode. Le corpus actuel (100% films) n'a jamais exercé ce chemin : la première série non-classique uploadée échouera. La constante SERIES_META_CATEGORIES = {2,6,14,15} existe déjà dans unit3d_mapping.py:56 et n'est PAS utilisée ici.
- *Solution* : Remplacer `if self.category_id == 2:` par `if self.category_id in SERIES_META_CATEGORIES:` (import depuis unit3d_mapping) + test unitaire paramétré sur les 4 cats + les cats film (7/13 doivent rester omis, règle Laravel prohibited_if). — effort **S**

**F004 · [B3 Mapping API] Livres : le payload envoie un type_id VIDÉO (BDRip=3) — book_type_id_for ne sert qu'à l'affichage, jamais à l'upload**
- *Où* : src/flox_uploader/core/upload_orchestrator.py:456 (build_upload_payload) vs src/flox_uploader/web/app.py:627 (affichage seulement)
- *Preuve* : build_upload_payload : `type_id = unit3d_mapping.type_id_for(bundle.release_name)` (heuristique vidéo, défaut BDRip=3) + override seulement si state.manual_type_id > 0. Le pipeline livre persiste manual_category_id=12 (pipeline.py:963-978) mais JAMAIS manual_type_id. Pendant ce temps l'UI affiche « Livre (27) » via book_type_id_for (web/app.py:620-643) : divergence affichage/POST. grep confirme : book_type_id_for n'a AUCUN consommateur dans upload_orchestrator.

**F005 · [B4 Upload/Dedup] Route web upload : 409 sur les 52 packages au .torrent raccourci (fix D.46 incomplet)**
- *Où* : src/flox_uploader/web/app.py:2830-2851 (api_package_upload)
- *Preuve* : La route fait `torrent_file = target / f"{state_data.release_name}.torrent"` puis 409 si absent, alors que _torrent_path_for (upload_orchestrator.py:240-264) a le fallback D.46. Script reproduisant la logique exacte de la route sur le corpus : « Packages non-uploades que la route web 409-erait alors que l'orchestrateur trouverait le .torrent via fallback D.46 : 52 ». ### 6.3 Perf / scalabilité mesurée (casquette D + lead)

  3-5 s → O(n × debug.json). `/api/command-palette` = 1,8 s.

## 10. Propositions créatives (au-delà de la correction)

Sélection des meilleures idées remontées, dédupliquées et priorisées.

1. **Split du score en deux sous-scores** affichés : « Conformité du nom » (charte)
   et « Richesse de la fiche » (TMDB/images), bucket = min des deux. Résout
   mécaniquement l'inversion dup/TMDB et le cas « nom parfait, fiche pauvre à 49 ».
2. **`flox-uploader recheck` / audit des uploadés** : re-passe la compliance
   corrigée sur les 216 packages déjà `uploaded` → sort la liste à risque
   (l'encode EXTREME 26362 sortirait immédiatement) avant que les modos ne la
   trouvent. Les noms sur le tracker sont renommables après coup.
3. **Golden corpus de non-régression** : geler 30-50 packages (entrée → release
   name validé par Louis, tous types) en fixtures paramétrées — généralise
   `test_release_name_real_cases.py` avant d'attaquer E-H. + golden payloads (1
   snapshot JSON par catégorie).
4. **`scripts/status_snapshot.py`** régénère le bloc chiffré de `docs/STATUS.md`
   (version, tag, tests, routes, corpus) entre marqueurs AUTO → **la doc ne peut
   structurellement plus mentir**. Même vérité exposée dans `/api/diagnostic`.
5. **Encart « Décision langue »** sur la page détail : chaîne de preuve complète
   (tag source → NFO → TMDB → règle → tag final), pas seulement les pénalités —
   seul moyen pour Louis d'attraper une conversion VOx douteuse avant upload.
6. **Gap-scanner intégré à l'inbox** : « Scanner ce dossier contre Gemini » croise
   la cascade dedup existante avec le browser → chaque fichier classé
   Safe/Risky/Danger. Fusionne UNIT3D-Upload-Checker dans le workflow.
7. **Injection qBittorrent + seed health check** : au-delà du watch-folder, POST
   `torrents/add` avec `skip_checking`, puis vérifier 10 min après que le torrent
   annonce et seed — **aucun concurrent ne ferme cette boucle**.
8. **Screenshots vidéo (ffmpeg) + upload images** : table stakes chez 100 % des
   concurrents, absent de Flox pour la vidéo (les livres ont déjà des previews).
9. **Compliance-as-code publiable** : extraire le moteur de checks Gemini (3
   sévérités, PDFs = vérité, `rules.json`) en linter standalone. Si le staff
   Gemini l'adopte, Flox devient l'outil de référence de facto.
10. **Bouton « Tout est VFF »** sur la queue : action batch `force_fr=VFF` sur les
    N packages `lang_needs_choice` sélectionnés → 88 allers-retours en 1 clic,
    toujours human-in-the-loop.
11. **Backup / export data** : carte « Mes données » dans `/config` (chemin,
    taille, ouvrir dossier, exporter ZIP config+historique) — règle le trou
    « perte disque = perte passkey + historique ».
12. **Signal `srrdb` positif** : si le nom reconstruit par Flox == nom scene
    canonique de srrdb, badge « certifié scene » + bonus score. Les concurrents
    utilisent srrdb pour corriger ; Flox serait le premier à l'utiliser pour
    **prouver**.
